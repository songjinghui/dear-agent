# 通用会话档案格式（Personal Conversation Archive）

当前版本：`1.1`（导入器同时兼容 `1.0`）  
文件编码：UTF-8  
文件格式：JSONL（每行一个 JSON 对象）

本格式用于在会话工具之间携带历史会话。转换工具负责将来源材料整理成此格式；导入程序只校验本格式的结构和字段，不读取或核对平台原始导出。

## 文件与分片

- 单文件使用 `.jsonl` 或 `.ndjson` 扩展名；一个文件可包含多个会话。
- ZIP 包包含 1 到 100 个 JSONL/NDJSON 分片，并可包含 `media/` 下的图片；所有分片使用同一个 `archive_id`。
- 单个分片不超过 100 MiB；ZIP 上传文件不超过 100 MiB，解压后不超过 500 MiB；整个档案最多 100,000 条消息。单条 JSONL 记录最多 5 MiB。
- 图片仅支持 JPEG、PNG、GIF、WebP；单张不超过 20 MiB，整个档案最多 10,000 张。只有 ZIP 能携带图片；JSONL/NDJSON 不能引用电脑上的外部路径或网络 URL。
- 大档案按会话或消息顺序拆分。每个分片都包含格式头；同一个会话跨分片时重复它的 `conversation` 记录。`message.id` 和 `sequence` 在各分片之间保持稳定且不重复。
- `part_index` 从 1 开始，`part_count` 是档案的分片总数。所有分片的 `part_id` 唯一。

## 记录类型

每个分片第一条非空记录必须为 `archive`。JSONL 中的记录顺序不影响分组；消息以 `conversation_id` 归属，以 `sequence` 排序。

### 格式头

```json
{"type":"archive","format":"personal-conversation-archive","version":"1.1","archive_id":"export-2026-10","part_id":"part-001","part_index":1,"part_count":1,"source_platform":"Gemini"}
```

必需字段：`type`、`format`、`version`、`archive_id`、`part_id`、`part_index`、`part_count`。`source_platform` 可省略。

### 会话

```json
{"type":"conversation","id":"conversation-001","title":"旅行安排","created_at":"2026-09-18T08:30:00+08:00"}
```

`id` 必需且在同一档案内稳定；`title` 可用“未命名会话”；`created_at` 可用带时区的 ISO 8601 日期时间或 `null`。如果一个会话分布在多个分片中，每个包含其消息的分片都应带上相同的会话记录。

### 消息

```json
{"type":"message","id":"message-001","conversation_id":"conversation-001","sequence":1,"timestamp":"2026-09-18T08:31:12+08:00","speaker":"user","speaker_label":null,"content":"原始消息全文","attachments":[{"id":"attachment-001","type":"image","path":"media/photo-001.jpg","filename":"旅行照片.jpg"}]}
```

必需字段：`id`、`conversation_id`、`sequence`、`speaker`、`content`。`id` 在档案内稳定且唯一；`sequence` 是每个会话内从 1 开始的整数。`speaker` 仅允许 `user`、`assistant`、`system`、`tool`、`unknown`。`speaker_label` 可保留来源中的角色名称。`timestamp` 为带时区的 ISO 8601 日期时间或 `null`；只有日期时填 `null`，避免补出具体时刻。

`content` 必须为字符串；一条消息记录只能包含一个说话方的一次发言。用户发言和 AI 回复必须分开记录，不能把 AI 回复拼进用户消息，也不能用空的 AI 消息记录代替来源中的真实回复。导出界面的时间戳应放在 `timestamp` 字段中，而不是拼进正文；如果来源没提供该条消息自己的时间，就填 `null`。

会话转换时，必须依据来源中可验证的消息对象、角色字段或消息容器来切分。URL/链接、空行、正文里的时间文字、Markdown 标记和话题变化都只是消息内容，不能单独作为消息边界。

```jsonl
{"type":"message","id":"m1","conversation_id":"c1","sequence":1,"timestamp":"2026-01-11T22:51:06+08:00","speaker":"user","speaker_label":null,"content":"请总结这个链接：https://example.com/article"}
{"type":"message","id":"m2","conversation_id":"c1","sequence":2,"timestamp":null,"speaker":"assistant","speaker_label":"Gemini","content":"我可以帮你总结；请提供网页正文。"}
```

上例中，链接完整保留在用户消息正文中，并不构成切分边界。`null` 表示来源没有提供 Gemini 回复自己的时间；不能因此把整条对话时间复制给 Gemini，也不能把回复文字并到用户消息中。1.1 消息可选包含 `attachments` 数组；每个图片对象包含档案内唯一的 `id`、`type`（`image`）、ZIP 内相对路径 `path` 和展示名 `filename`。图片文件必须随 ZIP 放在 `media/` 目录下，路径区分大小写，且不能使用 `..`、绝对路径或本机路径。旧版 1.0 消息不需要该字段。导出内容中的 AI 回复也作为原始消息保留，并保留其说话方。

导入器会校验文件签名、扩展名和大小，然后把图片复制到 Agent 自己管理的本地附件目录；不会引用原电脑的下载目录。预览按会话展示最多 3 张缩略图和图片总数；导入后图片显示在对应原始消息下，点击可放大。图片本身不会被 OCR 或自动发送给模型。

### 摘要（可选）

```json
{"type":"summary","id":"summary-001","conversation_id":"conversation-001","content":"独立保存的摘要","based_on_message_ids":["message-001"]}
```

摘要与消息分开存储。`based_on_message_ids` 可为空；有来源时列出其依据的消息 ID。导入的摘要不会自动升级为用户确认的长期记忆。

## 导入时的结构检查

导入器检查 UTF-8/JSONL、格式名和版本、字段类型、记录 ID、会话引用、消息顺序号、分片一致性和大小限制。每个分片以事务方式导入，失败时该分片不会留下部分记录；已成功导入的分片可以安全重试或继续导入其余分片。错误报告指向分片、行号和字段。导入器不与原平台文件对照，也不判断转换是否改写、遗漏或正确概括了原文。

相同 `archive_id` 与 `part_id` 的相同文件重复导入会识别为已导入；同 ID 对应不同内容时会报冲突。换一份重新转换的档案时，请使用新的 `archive_id`。

## 完整示例

```jsonl
{"type":"archive","format":"personal-conversation-archive","version":"1.1","archive_id":"example-001","part_id":"part-001","part_index":1,"part_count":1,"source_platform":"Example"}
{"type":"conversation","id":"c1","title":"示例会话","created_at":null}
{"type":"message","id":"m1","conversation_id":"c1","sequence":1,"timestamp":"2026-01-11T22:51:06+08:00","speaker":"user","speaker_label":null,"content":"请总结这个链接：https://example.com/article"}
{"type":"message","id":"m2","conversation_id":"c1","sequence":2,"timestamp":null,"speaker":"assistant","speaker_label":"Example AI","content":"我可以帮你总结；请提供网页正文。"}
{"type":"summary","id":"s1","conversation_id":"c1","content":"用户开始了一段对话。","based_on_message_ids":["m1","m2"]}
```

有图片时，将图片文件一并放进 ZIP 的 `media/` 目录，并在对应 `message.attachments` 中填写其档案相对路径。不要使用本机 Downloads 路径、`file://` URL 或远程图片 URL。
