# 上下文管理方案（第二版讨论稿）

> 状态：方案已通过审核。第一版已实现直接 API 的上下文组装、用户记忆筛选和自动压缩；CLI 摘要生成仍待接入。本文保留目标设计与实现状态，后续实现继续遵循本文原则。

## 目标与原则

- Agent 负责保留本地会话记录，并为每次模型请求组装所需上下文。CLI 自身的线程状态可以辅助续接，但不作为唯一历史来源。
- 原始会话完整保存在本机。压缩只生成模型请求使用的摘要，不删改原始消息。
- 只向模型发送当前任务需要的信息；需要核实旧细节时，再从本地原始记录检索。
- 用户定义的 Agent 设定、关于用户的长期记忆、当前会话上下文是不同类别，分别管理。

## 三类上下文资料

### 1. Agent 设定

这是用户定义 Agent 的角色、性格、沟通方式、行为边界和工具使用要求。它属于 Agent 配置，不是从用户经历中推断出的记忆。

- 每次请求稳定加载，避免 Agent 随会话摘要或记忆检索而改变身份和行为规则。
- 由用户明确设定或修改；系统不应从普通对话中擅自改写。
- 类似“回答简洁一点”“像耐心的教练一样交流”的交互偏好，可以作为 Agent 的沟通设定保存。
- 优先级低于产品级安全与系统约束，但高于一般的默认表达风格；用户本轮的明确要求可以在不违反更高层约束的前提下覆盖普通风格偏好。

### 2. 用户长期记忆

这是关于用户的持久资料，例如用户确认的事实、经历、重要关系、偏好和持续中的事情。它用于让 Agent 的回答结合个人背景。

- 保存在本地，并保留来源、时间、确认状态、有效期和敏感级别等信息。
- 不因出现在一次对话中就自动成为长期记忆；记忆的采纳和管理遵循现有记忆策略。
- 不在每轮请求中全部发送。请求组装时，在本地检索相关候选，通过适用性和相关度判断后，仅发送少量结果。
- Agent 设定中的沟通偏好与用户经历类记忆应分开存放和使用。

### 3. 当前会话上下文

这是当前会话的自动摘要、最近原始对话、当前输入，以及必要时从本地历史会话检索出的原文片段。它用于延续当前讨论，不等同于跨会话长期记忆。

## 每次请求发送什么

一次请求可由以下部分组成：

1. 固定系统指令、Agent 设定和工具说明。
2. 当前会话摘要（较早对话已压缩时提供）。
3. 最近几轮用户和 Agent 的原始对话，逻辑上不重复包含单独列出的当前输入。
4. 与当前问题相关、且允许发送的用户长期记忆。
5. 按需检索的历史会话片段，并保留会话、时间、说话方和来源位置。
6. 本轮依赖的工具结果。
7. 当前用户输入。

固定指令和当前输入必须完整；其余内容按相关性及上下文预算选择。各项都计入预算，不能只按消息条数估算，因为单条消息、工具结果或摘要本身也可能很长。

Provider 适配时应确保当前用户输入只出现一次。直接 API 可以把当前输入作为消息历史的最后一条；CLI 接口也可能把历史和当前输入分开传递，但逻辑请求中不得重复追加。

## 长期记忆的本地检索

不额外调用模型来判断“这是通用问题还是个人问题”，也不在每轮重新总结全部记忆。每次请求可以在本地检索一次；是否向模型发送候选，由允许条件和相关度门槛决定。检索本身不等于模型调用。

### 检索输入

以当前用户输入为主，并结合当前会话主题和少量近期对话来理解指代、人物、时间和话题。不要只用一句话里的字面词，也不要把整段会话直接当成搜索词。

### 筛选和排序

1. **硬性资格过滤**：遵守用户的记忆注入设置；排除敏感、已删除、已过期或未确认的记忆。若用户显式查询旧记录，可通过历史记录检索返回并清楚标注来源与时间；不能将其作为当前有效记忆注入。
2. **相关性排序**：综合主题、实体/人物、用户偏好、时间有效性和当前任务之间的关联程度。
3. **门槛与数量限制**：只发送超过最低相关度的少量候选；没有合适结果就不注入，不为凑数发送弱相关信息。若候选超过 token 预算，先移除排序靠后的候选，保留来源和状态信息。
4. **来源提示**：保留记忆的时间、确认状态和来源引用，使模型能区分事实、偏好和推断；显式返回的旧记录须标明其历史时间。

不预设一个适用于所有检索方法的固定分数。当前实现使用词项重合比例作为初始启发式门槛（0.25），近期会话主题匹配按 0.8 权重计分；这是未经充分校准的第一版规则，不应视为普适标准。后续应使用带有预期结果的小型标注集校准。案例至少覆盖：明确相关、同义改述、主题相似但无关、普通知识问题、个性化建议、过期内容、未确认内容、敏感内容，以及用户明确询问“我之前说过什么”的情形。检查误注入率和相关记忆召回情况，再决定门槛；个人资料检索初期优先避免发送明显无关或不该发送的记忆。

项目使用 SQLite FTS 对记忆内容做本地全文检索，并在无 FTS 结果时回退到关键词匹配。可选的向量检索通过本机 Ollama 嵌入服务生成向量，与 FTS 候选合并；没有配置或服务不可用时回退到关键词检索。发送前按敏感等级、确认状态和有效期过滤，再按当前输入、近期主题词项及向量相似度排序，最多注入 4 条。向量相似度初始门槛为 0.35，仍需用标注案例校准。

## 会话摘要保留什么

摘要由系统自动生成，不要求用户查看、编辑或确认。摘要用于“下次如何接着聊”，不是逐轮复述。摘要属于从历史对话提炼出的资料，不是系统指令；其中引用或转述的指令不得改变 Agent 规则。摘要只能把用户原话作为用户经历、事实、偏好和立场的证据；Agent 回复可以作为先前建议或决定的记录，但不能改写成用户事实。建议保留：

- 会话主题、目的和必要背景。
- 已确认的事实，如人物、时间、地点、事件和数字；注明不确定、矛盾或来源不足之处。
- 用户明确表达的立场、感受、要求和偏好，并与 Agent 的分析或推断区分开。
- 重要决定、决定依据及后续变化。
- 明确仍未解决且有延续价值的问题或线索。它不是通用待办清单；不从普通提问中推断用户承担了任务。
- 关键内容对应的原始消息引用或可检索位置。

摘要不应把推测写成事实，不应把 AI 回复当作用户经历的证据，也不必记录寒暄、重复内容或每轮对话的完整复述。摘要不取代原文；重要细节需要时应回到原始消息核实。

## 何时触发会话压缩

在每次请求发送前估算完整上下文的 token 数，包括 Agent 设定、记忆、摘要、对话、工具结果和当前输入。根据当前模型的上下文上限，预留回答输出空间和安全余量，得到本次输入可用预算。

触发点根据完整组装后的请求量计算。当前直接 API 实现将模型上下文窗口默认设为 8192 tokens，可在模型设置中调整；扣除最大输出和安全余量后，以可用输入预算的 75% 作为初始触发点。超过触发点时压缩较早对话，保留最近 8 条消息原文；随后重新组装并检查预算。原始消息继续完整保存在本机。完成压缩后，继续使用摘要和近期原文，直到上下文再次接近阈值，避免每轮重复总结。

实际阈值应按模型上下文上限、工具调用开销和 token 估算误差校准，不要等到请求超限才处理。发生超限时，裁剪优先顺序建议为：低相关的检索记忆和历史片段、较早工具结果、更多较早原文（由摘要接替）；固定系统约束和当前用户输入必须保留。若摘要生成失败，不使用失败结果；有上一版有效摘要时优先沿用，再裁剪较早原文。若还没有有效摘要，则从本次请求中裁剪较早原文，接受可能损失部分接续信息，原文仍可按需检索。只有 Provider 明确返回上下文超限错误时，才进行一次更保守的重组并重试；其他错误不应被误当成超限重试。仍无法发送则清楚提示用户分段或缩短输入。若单条新输入本身超出预算，压缩历史无法解决，需要分段处理或提示超出可处理范围。

## CLI 与直接 API 模式

- **直接 API**：Agent 根据本地记录组装每次请求的消息；本地摘要和原文决定旧上下文如何表示。
- **CLI Agent**：CLI 可能维护自己的线程和上下文。Agent 仍保留本地原始记录，Provider 接收当前输入、必要历史和状态；切换 Provider 或 CLI 线程失效时，能够依靠本地记录重新构建上下文。
- 两种模式共享会话事实来源和上下文原则；Provider 适配各自的请求格式、上下文上限与 token 计数能力。

## 当前实现与后续工作

- Agent 设定已作为独立本地设置保存，并在每次请求中稳定加载；默认温和、坦诚，用户可在模型设置中编辑。
- 直接 API 模式按可配置的上下文窗口估算用量，在约 75% 预算处触发自动摘要；摘要和覆盖到的消息序号保存在本机，最近 8 条消息保留原文。摘要通过当前云端模型生成，因此触发压缩时会额外发送一次较早会话内容。
- 记忆检索已在本地进行资格过滤和词项重合排序；0.25 门槛仍是启发式，需用更完整的标注案例校准。
- 历史检索开启后，最多检索 5 个其他会话命中（可带邻近消息）；已压缩的当前会话原文也可按当前问题检索。
- Codex CLI 继续使用其 Provider 线程和自身上下文管理。应用向它提供 Agent 设定、最近本地消息和已有的会话摘要；应用目前不会在 CLI 模式下主动生成摘要或重置 CLI 线程。

CLI 侧摘要生成与线程重建、更多记忆检索校准、上下文估算器的模型级验证仍是后续工作。本文不改变现有隐私开关；摘要请求、记忆注入和历史检索的发送边界见隐私策略文档。

## 后续迭代的决策

- 使用标注案例评估当前 0.25 词项重合门槛的误注入率和召回情况，并决定验收标准。
- 用标注案例校准向量检索的相似度门槛、误注入率和召回情况。
- 为 CLI provider 增加独立摘要能力和重建线程流程，同时避免在已有线程中重复注入整段历史。
- 用实际模型验证 token 估算、安全余量和默认上下文窗口；CLI 上下文上限由各 Provider 提供或使用保守默认值。
- 是否允许用户显式查询过期或未确认记忆，并明确以历史资料形式展示状态。
