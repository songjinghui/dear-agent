# V1 验收数据包（已确认策略版）

这套数据服务于 [`V1验收策略.md`](../../V1验收策略.md)，不包含真实私人信息。它把“给模型看的自然对话”和“给验收者看的正确事实”分开保存：执行时只打开输入脚本；完成一次运行后再打开判定表。

## 用什么方式测

采用**混合方法**，但发布前的用户验收以页面操作为准：

| 层次 | 工具与入口 | 负责验证 |
| --- | --- | --- |
| 自动回归 | 后端 `unittest`、前端 `npm test` 与 `npm run build` | 实现规则没有退化。 |
| 页面验收 | 浏览器中的拾光页面 | 用户能否完成聊天、查看加载与 Markdown、管理候选记忆、导入档案和继续对话。模型行为脚本也逐条从输入框发送。 |
| 接口/数据库复核 | 隔离数据目录的模型调用记录、会话摘要与本地数据库 | 调用是否真的发生压缩、严格私密内容是否没有进入请求、导入状态和来源是否可追溯。只作取证和建置，不把接口成功当作用户验收通过。 |

因此，不会用“直接调用 `/api/chat` 成功”来代替页面验收；也不会因为页面能点通，就放弃检查本地调用记录里的隐私与压缩证据。

## 一次完整执行顺序

1. 新建一个“验收轮次”隔离数据目录，启动应用；不要使用日常 `data/`。一轮包含 A-01 至 A-09 的全部执行，不会为每个用例新建数据库。
2. 在页面的模型设置中固定本次 Provider、模型、温度、上下文窗口和最大输出，并记录下来。A-03 建议使用 OpenAI 兼容的直接 API、`context_window_tokens=4096`、`max_tokens=350`，以便能观察到应用自己的压缩流程；Codex CLI 另按 A-09 验收，不把它当作同一项证据。
3. 先运行项目的自动回归；之后才开始手工页面验收。
4. 对 A-03，逐条在页面发送 [`a03-live-dialogue.md`](a03-live-dialogue.md) 的“执行输入”；每一条都等上一条回答完成，再发送下一条。不要把判定表内容贴进对话。
5. 对 A-04/A-05/A-08，在页面的“历史档案”导入 [`a04-a05-a08-trip-history-repeats.jsonl`](a04-a05-a08-trip-history-repeats.jsonl)。它提供三条内容相同、来源 ID 不同的“十一月出行”会话；每个重复只继续其中一条，再从输入框发送 `a04-a05-final-probes.md` 的问题。
6. 对 A-06/A-07，按 `a06-a07-ui-inputs.md` 在页面生成候选和创建测试记忆，再在页面完成分组确认、敏感记忆的本轮确认和严格私密排除检查。
7. 最后才打开 [`oracles.md`](oracles.md) 判定，并保留聊天截图、导入结果截图、模型调用记录和本地摘要记录。A-03 至 A-05 均独立重跑 3 次；任一次出现捏造、旧事实被当作当前事实、或严格私密泄露，即为失败。
8. 结束一整轮后，固定数据库与证据目录，并生成该轮报告；报告将本轮的用例结果与上一轮报告逐项对照。

## 一轮验收的身份、隔离与报告

一轮的标识是 `round_id`，而不是单个用例的标识。例如：`v1-20261028T070700+0800-r01-8f31c2`。其中 `r01` 表示第 1 轮完整验收；A-03 的第 2 次重复只是这轮内部的 `A-03/repeat-02`，不会单独新建数据库。

```text
data/acceptance/v1/rounds/<round-id>/
├── companion.sqlite3        # 本轮唯一的测试数据库
├── manifest.json            # 轮次身份、固定配置、输入数据哈希、代码版本
├── evidence/
│   ├── A-03/repeat-01/      # 截图、原始回复、调用记录定位
│   ├── A-03/repeat-02/
│   └── …
└── report.md                # 本轮汇总与同上一轮的差异
```

同一轮的逻辑隔离由测试顺序和来源映射保证：每个用例都新建会话；报告写入实际 `session_id`、导入 `archive_id`、模型调用记录 ID 与证据目录。A-01 至 A-06 在关闭长期记忆发送的前提下完成，A-07 的隐私记忆测试置于末尾，避免已确认记忆干扰前面的行为用例。读取任何证据时，以 `round_id + case_id + repeat` 精确定位，不使用“最近一次”。

`report.md` 至少包括：轮次时间、应用提交版本、数据包哈希、Provider 与参数快照、每个用例的三态（通过/失败/未执行）、原始回答和证据位置、失败分类，以及与上一轮同一用例的结果差异。没有上一轮时明确标记为基线，不伪造“改善”结论。

## 数据边界

- 每一轮重跑都使用一个新隔离目录；同一轮的全部用例共用该轮数据库，但按上文的会话、顺序和来源映射逻辑隔离，避免候选、摘要或记忆互相污染。
- 输入脚本只给出自然的用户表达，不含“正确答案”“不要出错”等纠正模型的元指令。
- `oracles.md` 和本说明中的预期不得复制到聊天输入框。
- 旧的 `../v1-acceptance-archive.jsonl` 是废弃草稿，不参与本次验收。
