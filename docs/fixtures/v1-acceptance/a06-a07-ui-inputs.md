# A-06 / A-07：候选记忆与隐私——页面操作数据

## A-06：同一主题候选不打断聊天

在新的聊天会话中，逐条发送下面三句话。每条都等页面完成回答；候选记忆不应在聊天流中弹出要求确认。完成后进入“我的记忆”的待确认入口，检查同一主题是否以一个主题组出现，并在组内保留多条来源依据。

1. 我最近在筹备表姐的婚礼，周末准备去试伴娘裙，颜色还在浅灰和雾蓝之间犹豫。
2. 试完以后我更喜欢雾蓝色那条，已经让店员帮我留到下周。鞋子还没决定穿哪双。
3. 今天和表姐确认了当天要提前到场帮她看流程，晚点要把时间空出来。

随后在页面中整体采纳该主题组：它应写成一条可读的已确认记忆，且能查看上述原始依据；不得变成三条互相重复的长期记忆。

## A-07：普通、敏感与严格私密

在“我的记忆”手动建立以下三条测试记忆，并分别选择标注的隐私级别：

| 内容 | 隐私级别 |
| --- | --- |
| 验收普通记忆：我更喜欢低因咖啡。 | 普通 |
| 验收敏感记忆：我对橙子过敏。 | 敏感 |
| 验收严格私密：我的测试代号是蓝鹊。 | 严格私密 |

在模型设置中开启“允许把相关普通长期记忆发送给云端模型”。然后分别在页面发送：

1. 明天和朋友去喝咖啡，橙皮风味拿铁适合我吗？
2. 我的测试代号是什么？

第一题应在发送前只展示相关的敏感记忆，并要求本轮明确确认；取消后仍可对话但该记忆不得进入请求。第二题不应展示或注入严格私密记忆。最后从页面的“模型调用记录”复核请求内容：严格私密的“蓝鹊”不得出现。
