# V1 验收测试数据与记录（暂停使用）

> 此文件及其关联 JSONL 是在验收方法确定前创建的草稿，**不作为 V1 验收依据**。
> 请先阅读 `docs/V1验收策略.md`；待用例卡与判定表确认后，再由策略反推新的测试数据。

这是一份**不含真实私人信息**的验收数据包。它用于验证本机 V1 的核心体验，不应导入日常使用的 `data/companion.sqlite3`，也不应与真实记忆混用。

## 1. 隔离运行

从项目根目录另开一个 PowerShell，使用单独的数据目录启动服务：

```powershell
$env:COMPANION_DATA_DIR = Join-Path (Get-Location) "data\acceptance-v1"
backend\.venv\Scripts\python.exe -m uvicorn companion.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

此命令只会在 `data/acceptance-v1/` 创建测试数据库和附件；不要在已有服务占用 8000 端口时再启动一份。验收完成后保留该目录，作为可复核记录；若要从零重跑，改用一个新的隔离目录，而不是删除日常 `data/`。

## 2. 这份数据到底要测什么

这不是检查模型能否复述一句刚给出的事实。它针对 V1 最初要解决的三个问题：

| 目标 | 数据中的压力点 | 失败信号 |
| --- | --- | --- |
| 长对话不遗忘 | “最近的事”夹有十几轮旅行以外的自然闲聊 | 只记得最近闲聊，漏掉旅行中的关键进展。 |
| 时间与更新不混淆 | 10 月 5 日计划十一月、雪鞋未买；10 月 12 日改为十二月、雪鞋已下单 | 仍把旧计划当最新，或把十几天前说成“刚刚”。 |
| 不知道时不编 | 档案从未提及酒店 | 被问到酒店时，编出地点、预订状态或价格。 |

上传 [v1-acceptance-archive.jsonl](fixtures/v1-acceptance-archive.jsonl)。档案不带预写摘要，目的是让应用自己经历上下文压缩与检索；“睡眠调整”是另一会话，用于确认不同主题不会被混在一起。

## 3. 真实模型验收流程

1. 在「模型设置」选择 **OpenAI 兼容 API**，把“上下文窗口”设为 `2048`、“最大输出”设为 `400`。这会刻意让较早的对话进入 V1 的摘要与检索路径；Codex CLI 使用自己的线程上下文，不能用这项设置验证压缩逻辑。
2. 在「历史档案」导入本数据文件，选择「最近的事」，点击「继续此会话」。
3. 像正常做旅行规划一样发送：`我准备请假把这趟行程定下来。能不能把现在已经确定的、还在考虑的事情分开整理一下？顺便说说我最近一次改行程是什么时候。`
4. 再发送：`我之前有说过酒店订到哪里了吗？`
5. 最后像自然补充近况一样连续完成两轮对话：`我看了几家酒店，想住离村子近一点的地方，不过还没有定。`、`羽绒服我今晚再选，行程先按十二月第一周来准备。`，然后进入「记忆」。每一轮都等待当前回复结束后再发下一轮。

## 4. 通过条件

| 检查 | 通过 | 失败 |
| --- | --- | --- |
| 更新覆盖旧信息 | 使用“十二月第一周、雪鞋已下单”；仍把羽绒服和请假天数列为待定。 | 仍以十一月中下旬或雪鞋未买作为当前状态。 |
| 时间感 | 能指向 10 月 12 日是最近一次调整，并把它表述为历史记录。 | 称它为“刚刚”，或虚构没有出现的时间。 |
| 不瞎编 | 对酒店说明此前没有记录，而不是补出酒店信息。 | 断言酒店已订、猜测地点或价格。 |
| 主题记忆 | 聊天中不逐条打断；记忆页把后两条旅行补充归在一个待确认主题，侧栏显示主题数。 | 出现多次确认打断，或把旅行和睡眠混成一个主题。 |

候选主题的措辞可以不同；测的是它是否忠于时间线、承认未知、以及是否把同一持续事项作为一个整体。若失败，保留原始回复和模型调用记录，不要靠手工编辑把结果“修成通过”。

## 5. 其它功能的确定性验收

- 手动新增一条“严格私密”记忆，例如 `验收私密标记：不应发送给模型`；再发起普通对话并查看模型调用记录。严格私密内容不应出现。
- 新增一条临时测试记忆，编辑、删除后刷新页面；复制隔离数据目录作为备份，确认操作持久化。
