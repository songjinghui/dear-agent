# 拾光路线图

> 文档状态：持续维护
> 最后更新：2026-10-29（V1 v1.0.0）
> 追踪单位：一个条目对应一个用户可验证的结果；实现工作开始后，再关联具体 commit、测试或验收记录。

## V1：本地、可长期使用的个人陪伴 Agent

**版本目标：** 在 Windows 本机提供一个可信、可控的个人对话入口。用户能聊天、管理自己的记忆和历史档案，并按自己的配置使用模型；数据与高影响操作不由模型擅自决定。

| ID | 条目 | 状态 | 完成标准 |
| --- | --- | --- | --- |
| V1-01 | 本机聊天与模式 | 已实现 | 可创建和继续会话；聊天/管家模式由用户显式切换并持续显示。 |
| V1-02 | 模型 Provider | 已实现 | 支持 OpenAI 兼容 API 与本机 Codex CLI；Codex 采用本机 OAuth 登录与 `exec --json` 调用。 |
| V1-03 | 本地数据与隐私边界 | 已实现 | 会话、设定、记忆与档案保存在本机 SQLite；API Key 不写入数据库；敏感记忆遵循逐次确认与严格私密排除。 |
| V1-04 | 可审阅的长期记忆候选 | 已实现 | 日常对话产出候选而非自动写入；候选可查看、编辑、采纳或忽略。会话内按主题归组、整体采纳与完整依据保留均已验证；用户也可以查看、修改、删除既有记忆。 |
| V1-05 | 历史档案 | 已实现 | 可预览、选择导入、回看、继续会话；可手动生成摘要和候选记忆，并保留来源。 |
| V1-06 | 发布前验收 | 已实现 | 已在隔离本机数据目录完成聊天、超长会话压缩、记忆确认、隐私边界、档案导入/续聊和 Provider 边界验收，并保留原始证据。 |

### V1 记忆能力边界（已验证）

- 当前实现是**候选确认系统**：候选的生命周期为“待确认 → 采纳（写入）/ 忽略”，不会因为用户暂时没有处理就自动删除。
- 会话内按主题合并、整体采纳与完整依据保留已经实现；它不会成为跨全库的持久主题目录。
- 已保存记忆可带 `expires_at`；到期内容不会再被注入模型上下文，但尚未提供完整的归档、替代、历史版本管理界面。
- 全库主题整理、主题管理和已保存记忆的完整生命周期，归入 V2，避免在日常聊天中自动合并或打断用户。

### V1 不包含

- 通用 Tool calling、任意网页/文件系统访问或模型可自行执行的外部操作。
- 自动提醒、日历写入、发送消息等代表用户行动的能力。
- 公网暴露、远程访问和多设备同步。
- Windows 桌面壳。当前可用形态是本机 Web；桌面入口应单独立项，不作为 V1 验收前提。

## V2：让 Agent 能够围绕外部材料、生活计划与主题记忆持续协作

**版本目标：** 在不牺牲资料来源透明度和用户控制权的前提下，让用户能把外部启发带入对话，并用可审阅、低打扰的主题记忆支持长期协作。

| ID | 条目 | 状态 | 完成标准 |
| --- | --- | --- | --- |
| V2-01 | 链接资料卡 | 已确认方向 | 用户明确提交链接并要求讨论时，应用读取受支持的公开页面，展示标题、来源、可获得的正文/字幕与读取失败原因；模型只能基于实际取得的材料总结。 |
| V2-02 | 视频材料降级路径 | 已确认方向 | 有公开字幕时使用字幕；没有字幕时明确仅有页面信息，允许用户上传字幕、文字稿或媒体以获得可讨论的文本，绝不把评论或简介伪装成完整视频内容。 |
| V2-03 | 外部材料的对话上下文 | 已确认方向 | 资料卡内容作为带来源和覆盖范围的外部材料加入当前对话；不自动变成长久记忆，也不隐瞒缺失部分。 |
| V2-04 | 用户确认的计划与提醒 | 待决策 | 只有明确的任务模型、时间语义、持久化、通知渠道、取消/修改和逐项确认方案具备后，才进入实现。 |
| V2-05 | 持久主题目录与记忆归属 | 已确认方向 | 为主题建立稳定 ID、名称、摘要、状态与隐私边界；原子事实仍可独立查看，归入主题不意味着丢失原始依据。 |
| V2-06 | 全量主题整理预览 | 已确认方向 | 以分批检索的相关记忆和精简主题目录生成“新建 / 归属 / 合并 / 拆分”预览；用户确认后才写库，绝不把全量原始记忆一次性发给模型。 |
| V2-07 | 整理基线与低打扰提示 | 已确认方向 | 记录上次确认整理的基线；新增、采纳或编辑累计到阈值，或用户手动发起时，仅在“记忆”页提示可生成预览，不在聊天中弹窗或自动调用模型。 |
| V2-08 | 主题页与主题优先检索 | 已确认方向 | 提供主题列表、详情、重命名、移动、拆分、合并和归档；会话优先注入相关主题摘要，再按需取回带依据的细节。 |
| V2-09 | 已保存记忆生命周期 | 已确认方向 | 明确展示活跃、到期、归档、被替代等状态；到期不自动删除，历史和来源可追溯，敏感内容遵守既有隐私策略。 |
| V2-10 | 用户主动生成的自我画像 | 已确认方向 | 用户主动选择生成范围后，基于已确认且未过期的记忆生成带来源依据的画像快照；严格私密内容永不参与，敏感内容逐次确认。画像可查看、重生成、删除和回看版本，但不会自动反写为长期记忆或在聊天中自动触发。 |

### V2 的技术边界

- 先实现由应用显式触发的资料获取，不把它当成泛化 Tool calling。
- 只访问用户明确提交且受支持的公开 URL；不绕过登录、付费墙、访问限制或站点反爬机制。
- 每份材料必须保存来源 URL、读取时间、可用内容类型与覆盖范围；无法取得字幕不等于已理解视频。
- 若将来引入工具，首个候选只能是只读、窄范围的资料获取能力。所有写入日历、消息、文件或第三方帐户的工具必须另行设计权限、预览、确认、幂等和审计。

## 决策记录

| 日期 | 决策 | 理由 |
| --- | --- | --- |
| 2026-10-26 | Codex Provider 使用本机 `codex exec --json` 与 CLI OAuth。 | 复用用户已有的 ChatGPT Plus 登录，并保持应用自己的会话与数据管理。 |
| 2026-10-27 | V1 不引入通用 Tool calling。 | 当前核心价值是可控的本地对话、记忆和档案；泛化工具会过早扩大权限、失败处理与审计范围。 |
| 2026-10-27 | 链接资料卡列为 V2 优先能力。 | 用户需要把视频、文章等外部启发带入可信对话；该能力应以来源和内容覆盖范围为基础。 |
| 2026-10-27 | V1 的记忆范围收口为候选确认和会话内主题合并。 | 先消除逐条确认的打扰，不把未经用户确认的全库主题结构写入数据库。 |
| 2026-10-27 | V2 建立持久主题目录、整理预览与完整记忆生命周期。 | 让记忆在长期使用时保持可管理，同时坚持分批处理、用户确认和不打断聊天。 |
| 2026-10-27 | V2 增加用户主动触发的自我画像。 | 画像满足用户理解自身的需求，但只能是可追溯的派生快照，不能替代或污染原始记忆。 |

## 更新规则

1. 新需求先放入“待决策”或目标版本，并写出可验证的完成标准。
2. 开始实现时，将条目标记为“进行中”（可在状态表中临时使用），并关联工作分支或 commit。
3. 代码完成不自动等于条目完成；只有完成对应验收标准后才能标为“已实现”或关闭。
4. 改变版本目标、隐私边界或外部操作权限前，需要先更新本路线图与相应产品/隐私说明。
