# 会话历史转换指令

请根据我提供的平台会话导出文件和《通用会话档案格式》说明，将记录转换为符合该标准的 UTF-8 JSONL 文件；如有多个分片或包含图片附件，请打包为 ZIP。

转换要求：

1. **先检查来源结构，再转换。**先说明实际文件类型，以及从来源中确认的会话/消息边界、角色字段、时间字段和附件引用字段。结构化 JSON/HTML 数据优先按其原生消息对象、角色字段、ID 或页面消息容器解析；如果一个对象分别提供了用户输入和 AI 回复字段，将它们映射为两条消息。不得先把内容拍平成纯文本再猜切分规则。
2. **切分只能依据来源中可验证的消息边界。**一个 `message` 记录只对应一个说话方的一次发言。不得把 URL/链接、空行、时间文字、Markdown 标记、话题变化或假定的 user/assistant 交替当成边界。链接属于它所在消息的普通正文。若来源只有纯文本，只有在其中存在明确且可验证的说话方标签/分隔符时才按其切分；否则停止转换并报告边界无法确认，不得自行创造标准。
3. 逐条保留原始用户消息和 AI 回复的完整文本，不总结、润色、纠错、删减或补写消息内容。不能把 AI 回复留在 `user` 的 `content` 中，也不能生成空的 `assistant` 占位消息来代替真实回复。
4. 按原始会话边界创建独立 conversation；不要把多个会话合并成长会话。只有来源明确提供会话边界时才据此分组；边界不清楚时保留为一个注明未知边界的会话，不猜测。
5. 保留原始顺序。每个会话的 `sequence` 从 1 开始递增；为会话、消息和摘要生成在所有分片间稳定且唯一的 ID。
6. 说话方映射到 `user`、`assistant`、`system`、`tool` 或 `unknown`。来源角色名可放在 `speaker_label`，例如 `speaker:"assistant"`、`speaker_label:"Gemini"`。角色标签不能代替 `speaker`，也不要把 `user`、`Gemini` 等角色名拼进消息正文。无法确定角色时才使用 `unknown`。
7. 每条消息的时间要从来源中该条消息自己的元数据读取，转换为带原时区的 ISO 8601。来源只给日期时，或无法确定某条消息自己的时间时，填 `null`；不要把导入时间当作消息时间，也不要把一条消息或整轮对话的时间复制给另一条消息。来源展示在正文之外的时间戳属于元数据，不要拼入 `content`；只有它本来就是用户输入/模型回复的文字时才保留在正文。
8. 每个分片都输出格式头。分片共享同一个 `archive_id`，使用不同的 `part_id`，并正确设置从 1 开始的 `part_index` 和 `part_count`。可按会话拆分；长会话可按消息顺序拆分，并在每个相关分片重复会话记录。
9. 可选摘要必须放在独立 `summary` 记录中，并尽可能列出 `based_on_message_ids`。摘要不能替代或修改原始消息。
10. 输出前检查生成文件自身是否为合法 JSONL、字段是否符合说明、消息 ID 和顺序号是否重复、会话引用是否存在。逐条抽查 `speaker` 与 `content` 是否匹配来源；重点确认 AI 回复没有落在前一条 `user` 消息中、真实回复没有变成空的 `assistant` 记录、正文没有混入导出界面的时间戳。如果无法可靠分清消息边界，停止生成并说明来源格式需要澄清，不要猜测拆分。只报告你实际从提供文件中读到的记录数量；无法确定时明确说明。
11. 如果来源确实提供了图片文件，将其放入 ZIP 的 `media/` 目录，并在对应消息的 `attachments` 数组中引用 ZIP 内相对路径、唯一附件 ID 和原文件名。不得写入电脑本机路径、`file://` 或网络图片 URL。无法取得图片二进制时，不要伪造图片文件；保留来源中的文字说明，并明确报告未能携带的图片数量。

请直接生成可下载的 `.jsonl` 文件，或包含 JSONL 分片和实际图片文件的 `.zip` 文件，不要只把长内容贴在聊天回复中。转换过程可能涉及私人对话，请仅在我选择的服务中处理这些文件。

## 输出前示例核对

假设来源中先有用户发言“请总结这个链接：https://example.com/article”，稍后有 Gemini 回复“我可以帮你总结；请提供网页正文。”，应当生成两条独立记录。链接保留在它所属的用户消息正文中，不作为切分依据：

```jsonl
{"type":"message","id":"m1","conversation_id":"c1","sequence":1,"timestamp":"2026-01-11T22:51:06+08:00","speaker":"user","speaker_label":null,"content":"请总结这个链接：https://example.com/article"}
{"type":"message","id":"m2","conversation_id":"c1","sequence":2,"timestamp":null,"speaker":"assistant","speaker_label":"Gemini","content":"我可以帮你总结；请提供网页正文。"}
```

如果来源没有给出 Gemini 这条回复的独立时间，第二条的 `timestamp` 保持 `null`；不能把时间戳写进第一条正文，也不能把第二条回复并到第一条。
