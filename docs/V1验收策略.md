# V1 验收策略

> 状态：已确认。验收数据由本策略反推；数据文件本身不构成验收设计。
> 范围：V1 的本机对话、上下文、记忆、隐私与历史档案。
> 非范围：移动端、多端同步、全库主题目录和用户画像（均属 V2）。

## 1. 要验证的产品主张

V1 不是要保证模型永远正确，而是要验证：当对话变长、事实发生变化、用户隔一段时间再回来时，拾光仍能给出**有时间感、知道依据和边界、不会擅自记忆**的回应。

验收围绕下列风险，而不是围绕某个模型“复述正确答案”：

| 主张 | 用户风险 | 失败的定义 |
| --- | --- | --- |
| 时间有依据 | 将数天前的事说成刚刚发生 | 混淆消息时间、相对时间或事实先后。 |
| 长对话仍连续 | 摘要或截断后忘记关键历史 | 漏掉相关旧事实，或把无关近话当成答案。 |
| 新信息覆盖旧信息 | 继续采用已经被修正的计划 | 对同一事项使用已过时状态。 |
| 未知不编造 | 用看似体贴的回答填补空白 | 对没有依据的信息给出肯定性细节。 |
| 记忆可控且不出戏 | 频繁确认或把细节拆成大量条目 | 未确认即写入、聊天被确认打断、同一事项被错误拆散。 |
| 私密边界可信 | 私密内容泄露给外部 Provider | 严格私密或未获确认的敏感内容进入请求。 |

## 2. 测试层次与责任

| 层次 | 要证明什么 | 执行方式 | 通过规则 |
| --- | --- | --- | --- |
| 自动回归 | 规则、持久化、路由和边界未退化 | 后端单元/集成测试、前端测试、生产构建 | 全部通过。 |
| 功能验收 | 用户能完成一次关键操作 | 隔离数据目录中的手工流程 | 每项流程可完成，结果可截图或从本地记录复核。 |
| 模型行为评估 | 真实 Provider 在有歧义的上下文下是否可靠 | 受控情景、独立判定表、固定模型设置 | 高风险错误为 0；其余按用例阈值判定。 |
| 恢复与可追溯性 | 中断、删除和导入后不会静默丢失或伪造状态 | 手工模拟中断、删除、导入/续聊 | 状态和来源可见，失败不被伪装为完成。 |

自动回归验证实现；模型行为评估验证产品假设。两者不可相互替代。

## 3. V1 验收用例矩阵

| ID | 要验证的风险 | 用例类型 | 独立判定（oracle） | 数据设计要求 |
| --- | --- | --- | --- | --- |
| A-01 | 基础会话可靠性 | 自动 + 手工 | 用户消息、助手消息和中断状态均持久化且可恢复 | 普通短对话与主动断开各一例。 |
| A-02 | 回答呈现 | 手工 | 加载占位、流式文字、Markdown 和错误状态均可理解 | 不依赖模型固定措辞。 |
| A-03 | 长上下文连续性 | 模型行为 | 在较小上下文预算下仍取回与当前问题相关的旧事实 | 一项早期事实、至少 12 轮自然干扰对话、最后再追问。 |
| A-04 | 时间与事实更新 | 模型行为 | 较新的带时间信息覆盖较早版本；回答能说明时间先后 | 同一事项至少一次自然更新，时间间隔明确。 |
| A-05 | 不确定性与不编造 | 模型行为 | 对档案和记忆中不存在的信息明确说明未知 | 为查询字段保留真正空白，不能在消息中暗示答案。 |
| A-06 | 记忆候选体验 | 自动 + 手工 | 候选不自动写入、不打断聊天；同一持续事项整体确认并保留来源 | 同一主题的多个自然补充，另加一个无关主题。 |
| A-07 | 记忆隐私 | 自动 + 手工 | 严格私密永不发送；敏感内容仅在本轮明确同意后发送 | 普通、敏感、严格私密三类各一条。 |
| A-08 | 档案与续聊 | 自动 + 手工 | 导入、选择、继续、删除均保留正确的来源和边界 | 有时间戳、无时间戳、多个会话各一份。 |
| A-09 | 本地 Provider 边界 | 手工 | OpenAI 兼容 API 与 Codex CLI 都能完成基础对话；各自的会话续接语义不混淆 | 分别记录 Provider、模型、设置与结果。 |

## 4. 模型行为用例的执行规则

1. 每一轮完整验收使用一个新建的隔离数据目录和一个全新的 SQLite 数据库；同一轮内的各用例共享这份可追溯数据库，但必须使用各自的新会话、独立来源记录和固定执行顺序，不能让前一用例的上下文、候选或记忆影响后一用例。模型行为用例的三次重复在同一轮中以独立会话执行。
2. 固定 Provider、模型、温度、上下文窗口和最大输出；记录这些设置。直接 API 的上下文压缩测试单独执行，不能把 Codex CLI 的线程管理当作同一项证据。
3. 每个 A-03 至 A-05 用例至少运行 3 次独立会话。任何一次出现隐私泄露、明确捏造或将旧状态断言为当前状态，都记为失败，不用平均分掩盖。
4. 判定表在运行前写好，测试提问中不得包含“正确答案”“不要说错”或其他纠正模型的指令。
5. 保留原始回复、消息时间和模型调用记录；只记录“通过/失败”不足以定位问题。每轮结束生成一份报告，记录该轮的代码版本、测试数据版本、配置快照、各用例/重复的证据和相较上一轮的变化。

## 5. 数据生成规则

测试数据只能从本策略的用例反推，并遵守以下规则：

- **事实表与对话分离**：先写只给测试者看的事实表（当前事实、旧事实、未知字段、时间线），再写对话；模型只会看到自然对话，不会看到事实表。
- **一份数据只服务有限风险**：一个情景最多覆盖 A-03 至 A-05 的关联问题；隐私、导入格式和中断恢复使用各自独立数据，不把所有风险堆进一段剧情。
- **自然语言而非测试腔**：用户像正常生活中一样补充、改变主意或追问，不说“请不要误记”“这是测试”等元话语。
- **必须存在更新与空白**：有一项较早事实被后来更新；另有一项用户从未提及，作为未知性检查。
- **必须足够长**：用于 A-03 的对话要在设定的上下文预算下触发压缩/检索；不预填摘要，以免绕过被测机制。
- **来源可定位**：每条关键事实有原始消息 ID 和时间戳，便于判断模型是遗忘、时序错误还是无依据推断。

## 6. 数据产出顺序

1. 为 A-01 至 A-09 写出用例卡和判定表。
2. 由 A-03 至 A-05 的事实表生成自然对话档案；由 A-06、A-07、A-08 分别生成专项数据。
3. 校验档案格式、时间线、未知字段和长度是否满足用例卡。
4. 先跑自动回归，再做手工与模型行为验收；失败时保留证据并回到对应风险修复，不修改数据来迁就结果。
