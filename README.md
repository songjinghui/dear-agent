# 拾光：个人生活 Agent

一个先在 Windows 本机运行的生活陪伴应用。会话、导入历史档案和记忆保存在本地 SQLite 数据库；模型 API Key 通过 Windows 凭据管理器保存。支持 OpenAI 兼容 API，也支持调用本机 Codex CLI 的 `exec --json`。长期记忆和历史档案默认都不会附加到模型请求中；日常对话中发现的记忆候选会先征求用户确认，再写入长期记忆。

当前版本通过浏览器访问本机服务。Windows 桌面应用是后续入口方向：保留现有页面布局，由桌面应用自动启动服务并打开独立窗口；桌面打包尚未实现。

## 环境要求

- Windows 10/11
- Python 3.11 或更新版本
- Node.js LTS（用于构建/运行 Web 界面）

## 安装

在 PowerShell 中，从本目录运行：

```powershell
py -3.11 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -e backend
Set-Location frontend
npm install
npm run build
Set-Location ..
```

## 启动

在本目录启动本机服务：

```powershell
backend\.venv\Scripts\python.exe -m uvicorn companion.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

然后浏览器打开 <http://127.0.0.1:8000>。服务只监听本机地址，不会开放家庭网络或公网端口。

开发 Web 界面时，先按上文启动后端，再另开 PowerShell：

```powershell
Set-Location frontend
npm run dev
```

开发地址为 <http://127.0.0.1:5173>，API 请求会转发到本机后端。

## 首次配置

1. 在「模型设置」里选择 OpenAI 兼容 API，填写接口地址、模型名称、API Key 和上下文窗口大小；或者选择 Codex Agent，后端会通过本机 Codex CLI 调用 `exec --json`，沿用该 CLI 的 OAuth 登录，并显式使用 GPT-6 Astra。提示词通过标准输入传递，不出现在进程命令行中；API 默认使用 Chat Completions，依靠本机消息历史续接；选择 Responses API 后，会按本地会话保存服务端返回的 conversation ID，或使用 Responses API 的 response ID 作为 `previous_response_id` 续接。该模式会让模型服务端保留会话内容，应仅用于支持 Responses API 会话续接的服务。
2. Codex Agent 需要本机安装并登录 Codex CLI。每个应用会话会保存关联的 Codex thread，后续轮次通过 `exec resume` 续接；Codex 的本地工具限制在空的只读目录中。
3. API Key 会写入 Windows 凭据管理器，不会写入项目配置或 SQLite。
4. Agent 分为「聊天」和「管家」两种模式，默认聊天。可在对话输入框上方显式切换当前会话模式，也可在设置中修改新会话的默认模式。不会因聊天内容自动切换模式。
5. 「共用 Agent 设定」与关于你的长期记忆分开保存。你可以在模型设置中分别编辑共用设定、聊天模式提示语和管家模式提示语；相关设定随请求发送给所选模型。固定的独立判断和隐私边界不会被模式提示语覆盖。
6. 默认关闭「允许把相关普通长期记忆发送给云端模型」。匹配到敏感记忆时，应用会在发送前展示本轮将附加的具体内容，只有逐次确认后才会加入该次请求；取消确认会继续发送问题，但不带敏感记忆。授权仅对应当前记忆内容版本，不会保存为全局偏好。标为「严格私密」的记忆永不进入模型请求。未确认和过期记忆也会被排除。每次最多注入 4 条相关记忆。
7. 在日常对话中，模型会同时返回正常回复和结构化记忆候选。候选必须附有本轮用户原话作为依据，并标注工作、情景或语义类型及隐私级别；应用会过滤无效或缺少原文依据的候选，显示在对话中供用户修改、确认或忽略。只有确认后才写入长期记忆。说「记住这个：……」仍会按用户明确要求直接保存；也可以从「我的记忆」手动添加。记忆隐私级别可设为普通、敏感或严格私密。
8. 在「历史档案」选择符合[通用会话档案格式](docs/通用会话档案格式.md)的 JSONL/NDJSON 或 ZIP 分片包；图片随 ZIP 中的 `media/` 文件夹导入。预览按会话显示消息数和图片缩略图，勾选会话后确认导入。图片会复制到 Agent 本地附件目录。原平台导出需先由用户选择的 AI 按[转换指令](docs/会话转换提示词.md)转换。
9. 在「模型设置」单独开启历史档案检索后，当前问题匹配的最多 5 个历史命中才会附加到模型请求；压缩后的当前会话原文也可按需检索。此设置默认关闭。
10. 直接 API 模式会在上下文接近预算时自动生成会话摘要，摘要保存在本机并随之后的请求使用；原始消息仍完整保留。Codex CLI 继续使用自己的线程上下文管理。
11. 历史会话全部分片导入后，可点「继续此会话」在同一会话里接着聊。导入原文只读保留，新对话会标明为续聊；删除档案时原始消息会移除，续聊消息会保留为普通本机会话。
12. 在历史会话详情中可单独发起「生成摘要与记忆候选」。选中的会话会分批发送给当前配置的模型，分析结果和候选按批次保存，临时服务错误会自动有限重试。旧分析触及候选数量上限时，应用会在后台补扫遗漏的后续消息。完成后可按人物或主题整理候选，预览后逐组采纳；原始候选和出处会保留。只有采纳的内容才写入长期记忆，并附带原文消息出处。

## 数据位置

默认数据位于本目录的 `data/companion.sqlite3`，其中包含新会话、导入档案、长期记忆、共用及模式设定、自动生成的会话摘要、模型调用记录和按本地会话保存的 provider 会话标识。模型调用记录会自动保存发出的请求内容和处理结果，可在「模型设置 → 查看模型调用记录」中查看或删除；记录不会自动过期。原始消息会保留在本机；摘要用于后续直接 API 请求的上下文管理。`data/` 已加入忽略规则，不会被提交到版本库。备份时请复制整个 `data/` 目录到自己控制的安全位置。API Key 保存在 Windows 凭据管理器中，应另外通过系统账户和系统备份策略保护。

可选的语义检索通过本机 Ollama `/api/embed` 服务生成记忆向量，不会把记忆文本发送给云端嵌入服务。先在本机安装并启动 Ollama、下载一个嵌入模型，再在「模型设置」开启「本机向量语义检索」，填写模型名（例如 `embeddinggemma`）。应用会在本机缓存向量，并将向量检索与全文关键词检索合并；服务未配置或暂时不可用时回退到关键词检索。默认关闭向量检索。

记忆类型是另一条独立维度：设计包含工作、情景、语义和感知四类；当前记忆表和界面实现工作、情景、语义三类，感知记忆（照片、语音等）仍是后续能力。

更多隐私说明见 [隐私与记忆策略](docs/隐私与记忆策略.md)。产品范围见 [项目说明](项目说明.md)，版本范围与状态见 [路线图](docs/ROADMAP.md)。
本机 CLI 扩展方式见 [CLI Provider 插件接口](docs/CLI_PROVIDER_PLUGINS.md)。

## 运行测试

后端测试按用户功能组织在 `backend/tests/`，直接调用对应处理器并使用隔离的临时 SQLite 数据库，不依赖模型服务、Codex 登录或外部网络。进入 `backend/` 目录运行：

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

目前覆盖会话、设置、记忆、聊天中的明确记忆指令、Codex 会话失效恢复、档案预览与选择导入、档案格式与导入续聊、分析候选采纳等功能。新增或修改功能时，必须先建立或更新测试用例，再修改实现，并运行相关测试套件直至通过。

前端构建会执行 TypeScript 检查：

```powershell
Set-Location frontend
npm run build
```
